# 变量说明

## `ai_pilot_approvals.csv`

| 变量 | 含义 | 性质 |
|---|---|---|
| `pilot_id` | 本项目生成的试验区唯一编号 | 分析字段 |
| `cohort_id` | 按相同正式批复日期划分的组别 | 分析字段，不是官方批次 |
| `cohort_order` | 批复日期组的先后顺序 | 分析字段 |
| `scope_level` | 直辖市、地级市或县级 | 事实字段 |
| `scope_name` | 科技部批复覆盖的行政区域 | 事实字段 |
| `scope_gb_code` | 用于匹配的行政区划代码 | 匹配字段 |
| `province`、`province_code` | 所属省级行政区及代码 | 匹配字段 |
| `prefecture`、`prefecture_code` | 所属地级行政区及代码 | 匹配字段 |
| `county`、`county_code` | 所属县级行政区及代码 | 匹配字段 |
| `approval_date` | 科技部正式批复的成文日期 | 核心政策日期 |
| `approval_year` | `approval_date` 所在年份 | 分析字段 |
| `first_full_year` | 批复后的第一个完整自然年度 | 分析字段，不是官方生效日期 |
| `publication_date` | 科技部官网发布日期 | 事实字段 |
| `document_no` | 科技部批复文号 | 事实字段 |
| `index_no` | 科技部政府信息公开索引号 | 核验字段 |
| `recipient` | 批复收文单位 | 事实字段 |
| `policy_focus` | 根据正式批复归纳的重点方向 | 摘要字段 |
| `source_url` | 科技部正式批复链接 | 来源字段 |
| `checked_on` | 本项目最后核验日期 | 质量控制字段 |
| `notes` | 匹配和识别时需要特别注意的问题 | 说明字段 |

## `ai_pilot_city_year_2010_2025.csv`

这是由 `build_city_year.py` 从批复表机械生成的18个试验区行政区域年度面板。

| 变量 | 含义 |
|---|---|
| `ever_treated` | 该行政区域最终是否获批；本文件内恒等于1 |
| `post_approval_year` | 年份大于等于批复年份时取1 |
| `post_full_year` | 年份大于等于批复后第一个完整自然年度时取1 |
| `event_time_approval_year` | 年份减批复年份 |
| `event_time_full_year` | 年份减第一个完整自然年度 |

本文件只列出18个最终获批地区。与全国上市公司数据合并后，未匹配到试验区的企业应将 `ever_treated`、`post_approval_year` 和 `post_full_year` 赋值为0，但事件时间应保持缺失，而不是赋值为0。

## 日期编码原则

`approval_date` 是政策事实；`approval_year`、`first_full_year` 和两个 `post` 变量是研究者根据年度数据构造的分析变量。

对于年度财务数据，建议把 `post_full_year` 作为主设定，因为它避免把批复前月份也当作政策期。把 `post_approval_year` 作为替代口径进行稳健性检验。最终选择仍应结合结果变量的计量期间和政策作用机制决定。

## 特殊匹配规则

1. 北京、上海、天津、重庆按直辖市全域处理，企业数据中的省级代码和市级代码可能并存。
2. 德清试验区只覆盖浙江省湖州市德清县。若数据只有“湖州市”而没有县级地址，应将德清样本暂时排除，不能把湖州市全部企业视为处理组。
3. 企业所在地建议使用政策前固定的注册地或总部所在地，避免企业在政策后迁址造成处理状态内生变化。
4. 行政区划代码应与企业数据采用的代码版本核对；本表代码主要用于名称标准化，不代替历史行政区划核验。
